| price | 필수, 1000~500000 정수 | "가격은 1,000원~500,000원이어야 합니다" |
| description | 선택, 최대 500자 | "설명은 500자 이내여야 합니다" |

## 2. 상태 전이 규칙

### 주문 상태 (단방향)
```
pending → preparing → completed
```

| 현재 상태 | 허용 전이 | 비허용 전이 |
|---|---|---|
| pending | preparing | completed (건너뛰기 불가) |
| preparing | completed | pending (역방향 불가) |
| completed | - (최종 상태) | pending, preparing |

### 테이블 세션 상태
```
inactive → active → completed
```

| 현재 상태 | 전이 조건 | 결과 |
|---|---|---|
| 세션 없음 | 첫 주문 생성 | 새 세션 생성 (active) |
| active | 이용 완료 처리 | completed (주문 이력 이동) |
| completed | 다음 고객 첫 주문 | 새 세션 생성 (active) |

## 3. 인증/인가 규칙

### 관리자 인증
| 규칙 | 설명 |
|---|---|
| JWT 만료 | 16시간 후 자동 만료 |
| 로그인 실패 제한 | 5회 연속 실패 시 15분 잠금 |
| 잠금 해제 | locked_until 시각 경과 후 자동 해제 |
| 비밀번호 저장 | bcrypt 해싱 (cost factor 12) |

### 테이블 인증
| 규칙 | 설명 |
|---|---|
| 토큰 만료 | 16시간 후 자동 만료 |
| 비밀번호 저장 | bcrypt 해싱 (cost factor 12) |

### 인가 (Authorization)
| 엔드포인트 그룹 | 인증 요구 | 인가 규칙 |
|---|---|---|
| GET /api/categories, /api/menus | 테이블 토큰 | 해당 매장 메뉴만 조회 가능 |
| POST /api/orders | 테이블 토큰 | 해당 테이블로만 주문 가능 |
| GET /api/orders (고객) | 테이블 토큰 | 해당 테이블+활성 세션 주문만 조회 |
| POST/PUT/DELETE /api/menus | 관리자 JWT | 해당 매장 메뉴만 관리 가능 |
| PATCH /api/orders/{id}/status | 관리자 JWT | 해당 매장 주문만 상태 변경 가능 |
| DELETE /api/orders/{id} | 관리자 JWT | 해당 매장 주문만 삭제 가능 |
| POST /api/tables/{id}/complete | 관리자 JWT | 해당 매장 테이블만 완료 처리 가능 |
| GET /api/sse/orders | 관리자 JWT | 해당 매장 이벤트만 수신 |

## 4. 데이터 무결성 규칙

### 주문 생성 시
| 규칙 | 설명 |
|---|---|
| 메뉴 스냅샷 | 주문 시점의 메뉴명, 단가를 OrderItem에 복사 저장 |
| 총액 계산 | total_amount = SUM(quantity * unit_price) |
| 메뉴 유효성 | is_available=true인 메뉴만 주문 가능 |
| 매장 소속 확인 | 주문 메뉴가 해당 매장에 속하는지 검증 |

### 이용 완료 시
| 규칙 | 설명 |
|---|---|
| 원자적 처리 | 이력 이동 + 원본 삭제 + 세션 종료를 하나의 트랜잭션으로 |
| 이력 보존 | OrderHistory에 주문 항목을 JSONB로 직렬화하여 보존 |
| 세션 종료 | is_active=false, completed_at 기록 |

### 메뉴 삭제 시
| 규칙 | 설명 |
|---|---|
| 참조 무결성 | 기존 주문의 OrderItem은 menu_name/unit_price 스냅샷으로 보존 |
| 소프트 삭제 고려 | 현재는 하드 삭제 (스냅샷으로 이력 보존됨) |

### 주문 번호 생성
| 규칙 | 설명 |
|---|---|
| 형식 | YYYYMMDD-NNN (예: 20260506-001) |
| 순차 보장 | 매장별 당일 기준 순차 증가 |
| 고유성 | store_id + order_number 조합으로 UNIQUE |
| 리셋 | 날짜 변경 시 001부터 재시작 |
